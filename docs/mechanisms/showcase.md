# Mechanism: the public skill showcase

## What it is

The browsable marketplace website at GitHub Pages, generated from `catalog.json`. One
source of truth, no hand-maintained list, no server.

## The arrangement

| piece | role |
|---|---|
| `plugins/scout/skills/scout/catalog.json` | the compiled catalog (name, plugin, version, purpose, activates-when, best-for, needs, changes) — generated by `scripts/gen_catalog.py`, never hand-edited |
| `plugins/<domain>/skills/<name>/evals/result.json` | per-skill measured trigger score (`trigger.best_score`, `accuracy`, `baseline_accuracy`) |
| `scripts/gen_showcase.py` | reads the catalog + each skill's file tree (names only) + its `result.json`, emits the self-contained `showcase/index.html` |
| `showcase/index.html` | the generated page — committed so a PR previews it; rebuilt in CI |
| `.github/workflows/pages.yml` | rebuilds and deploys the page to GitHub Pages |

## What the page shows — and what it deliberately does NOT

Shows only curated, public-safe data: id, version, purpose, when-it-fires, best-for,
side-effect tags, dependencies, the file bundle (names + sizes only), and the measured
trigger score.

**The SKILL.md body is NOT embedded.** Bodies can carry real identifiers (namespaces,
ticket refs) and the site is public; `cerberus:leak-check` only runs on skill *edits*,
not on this export path, so a verbatim body dump would publish any pre-existing leak.
The page links to the body on GitHub instead of copying it. Effect and security-scan
The measured trigger score is shown, the security-scan checklist is shown per skill, and the skillaxe effect score is shown where it has been measured.

## The `[skip ci]` trap (why the trigger looks the way it does)

`catalog.json`'s only writer is scout-publish-bot, which commits as
`chore(scout): regenerate catalog … [skip ci]`. GitHub Actions' `[skip ci]` suppresses
**every** push-triggered workflow on that commit, repo-wide — so a push trigger on
`catalog.json` can never fire. `pages.yml` therefore does not trigger on `catalog.json`;
a **daily `schedule`** picks up version bumps, and the push trigger covers the generator,
the workflow, and `SKILL.md` edits. `workflow_dispatch` forces a manual rebuild.

## Change trigger

Editing `scripts/gen_showcase.py`, `pages.yml`, or what the page is allowed to show
updates this page in the same PR.
