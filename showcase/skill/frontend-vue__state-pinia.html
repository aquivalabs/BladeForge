Pinia setup-syntax stores, one per domain concept, with refs for state, computeds for derived values and actions for changes; explicit loading and error; shallow refs for large server snapshots; TanStack Query for Vue for server state when the project uses it.

see it

fires when

Use when a Vue app needs state that more than one component reads or writes — the current user or workspace, lists from the server, selections, filters, marks — or when creating, editing, reviewing or splitting a Pinia store, deciding whether something belongs in a store at all, loading server data into one, or wiring server state through TanStack Query for Vue. NOT for behaviour composables (frontend-vue:composables-vueuse), not for component-local state (frontend-vue:sfc-conventions).

best for

Vue 3 projects whose state crosses component boundaries and should be written and reviewed one way.
