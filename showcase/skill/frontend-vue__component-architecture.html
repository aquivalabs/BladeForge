frontend-vue:component-architecture v0.1.1

Where a Vue component lives and what it may know — pages, layouts, features, ui primitives, composables and lib — with imports going down only, reuse of primitives before new ones, and the split rule.

see it

fires when

Use before creating a Vue component or when deciding where one lives and what it may know — a reusable UI primitive, a feature component bound to the domain, a layout piece of the app chrome, a page or view, a component that only exists for one parent. Also when a component grew into two, when a feature reaches into another feature's component, when a page holds logic, or when asked \"where does X go\" in a Vue project. NOT for the inside of the .vue file (frontend-vue:sfc-conventions), nor for React (frontend-react:component-placement).

best for

Vue projects past a handful of components that want every new one placed by its knowledge, not by habit.
