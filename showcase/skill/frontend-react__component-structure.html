Standardizes how a React component's files, folder, BEM classes, and styling conventions are organized so structure stays consistent across the codebase.

fires when

Use when creating, editing, restructuring, or reviewing a React frontend component \u2014 including its folder layout and file organization (tsx/scss/index), where a component or sub-component should live, BEM class naming, SCSS styling, rem sizing, i18n of user-visible strings, barrel exports, and replacing inline JS style/hover handlers (e.g. onMouseEnter toggling classes) with CSS. Covers \"this component file is in the wrong place \u2014 fix the structure\", moving a flat .tsx into its own folder, and any question about how a component's files, styles, or markup should be organized.

best for

Teams building a React app who want every component (and sub-component) to follow the same folder/file/BEM/i18n/error-boundary conventions instead of drifting per-author.
