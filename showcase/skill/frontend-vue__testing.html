frontend-vue:testing v0.1.1

Which test goes where in a Vue project — units for lib and composables, Testing Library or Vue Test Utils for components by role and text, Pinia stores through actions, @nuxt/test-utils for Nuxt, Playwright for the few flows that matter — with boundaries mocked, time controlled, and one command before a merge.

see it

fires when

Use when writing, fixing or reviewing tests for a Vue project — a unit test for a composable or a lib function, a component test with Vue Test Utils or Testing Library for Vue, a Pinia store test, a Nuxt test with @nuxt/test-utils, an end-to-end flow with Playwright — or when deciding what to test at which level, what to mock, how to run the suite before a merge, or why a test is flaky. NOT for the toolchain configs themselves (frontend-vue:tooling) and NOT for Apex or React tests.

best for

Vue projects that want tests that survive refactors and a suite that gates a merge.
